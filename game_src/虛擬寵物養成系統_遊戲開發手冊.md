## 1. 遊戲概念

### 1.1 核心理念

消費者每次透過惜食系統購買食物都會獲得**點數**，這些點數可以在「寵物養成」小遊戲中消耗，達成：

- **增加用戶黏著度**：給消費者一個持續回來的理由
- **遊戲化減少浪費**：把「救食物」變成養寵物的資源，建立情感連結
- **社交傳播**：「我的寵物比你的等級高」→ 口碑行銷

### 1.2 玩法概述

```
消費者買食物 → 獲得點數 → 進入寵物頁面 → 消耗點數餵食/互動
                                              │
                                              ├── 餵食 → 寵物飽食度上升 → 觸發成長
                                              ├── 玩耍 → 寵物心情上升 → 解鎖動作
                                              ├── 裝飾 → 消耗點數購買配件
                                              └── 升級 → 外觀進化、解鎖新功能
```

### 1.3 設計原則

| 原則 | 說明 |
|------|------|
| **輕量休閒** | 不是硬核遊戲，每次互動 30 秒~2 分鐘 |
| **被動成長** | 即使不主動玩，寵物也不會死（只是停止成長） |
| **無付費牆** | 所有內容都靠惜食點數取得，不額外收費 |
| **低門檻** | 不需教學就能上手，點擊即互動 |

## 2. 技術架構

### 2.1 技術選型

| 層面 | 技術 | 理由 |
|------|------|------|
| **遊戲渲染** | PixiJS v8 | 輕量 2D WebGL 引擎，~200KB，CDN 載入，手機效能好 |
| **動畫** | PixiJS + GSAP | PixiJS 處理精靈，GSAP 處理 UI 過場動畫 |
| **音效（選配）** | Howler.js | 輕量音效引擎，~10KB |
| **狀態管理** | 純 JS 物件 | 遊戲狀態簡單，不需框架 |
| **與主系統通訊** | 共用 API 模組 | 呼叫主系統的 REST API |
| **載入方式** | CDN `<script>` | 與主系統一致，不引入額外打包工具 |

### 2.2 CDN 依賴

```html
<!-- PixiJS 核心 -->
```

## 3. 與主系統的整合介面

### 3.1 已存在的介面（你可以直接用）

| 介面 | 說明 | 端點 |
|------|------|------|
| **使用者點數** | 查詢當前點數 | `GET /api/v1/auth/me` → `user.points` |
| **JWT 認證** | 登入後取得 Token | 存在 localStorage `token` |
| **Hash Router** | 頁面路由 | `#/consumer/pet` 已預留 |
| **API 呼叫模組** | 封裝好的 fetch | `mobile/js/api.js` |

### 3.2 你需要新增的介面

| 介面 | 方向 | 說明 |
|------|------|------|
| `POST /api/v1/pet/feed` | 遊戲 → 後端 | 餵食（扣點數） |
| `POST /api/v1/pet/play` | 遊戲 → 後端 | 玩耍（扣點數） |
| `POST /api/v1/pet/buy-item` | 遊戲 → 後端 | 購買裝飾品 |
| `GET /api/v1/pet/status` | 遊戲 ← 後端 | 取得寵物完整狀態 |
| `POST /api/v1/pet/create` | 遊戲 → 後端 | 首次建立寵物 |

### 3.3 點數扣除的安全原則

> ⚠️ **所有點數操作必須在後端執行！**  
> 前端遊戲只負責顯示和動畫，不能自行修改點數。

```
前端：玩家點擊「餵食」按鈕
  │
  ├── 前端先檢查 user.points >= cost（UX 優化，避免無意義請求）
  │
  ├── POST /api/v1/pet/feed { item_id: 1 }
  │
  ├── 後端驗證：
  │   ├── JWT 有效？
  │   ├── 點數足夠？
  │   ├── 餵食冷卻時間到了？
  │   └── 扣點 + 更新寵物狀態（原子操作 transaction）
  │
  └── 前端收到成功 → 播放餵食動畫 + 更新 UI 點數
```

## 4. 遊戲機制設計

### 4.1 寵物種類

MVP 先做 **3 種寵物**，對應三大食物分類：

| 寵物 | 對應食物 | 外觀概念 | 解鎖條件 |
|------|----------|----------|----------|
| 🍙 飯糰兔 | 便當 (bento) | 圓滾滾的兔子，頭上有海苔 | 預設（註冊即送） |
| 🍞 麵包熊 | 麵包 (bread) | 吐司造型的小熊 | 累計購買 5 次麵包類 |
| 🥬 蔬菜龍 | 蔬菜 (vegetable) | 用蔬菜組成的小龍 | 累計購買 10 次蔬菜類 |

### 4.2 寵物屬性

```javascript
{
    pet_id: 1,
    species: "rice_bunny",      // 種類
    name: "小糰子",             // 玩家取的名字
    level: 5,                   // 等級 (1~30)
    exp: 320,                   // 經驗值
    exp_to_next: 500,           // 升級所需經驗
    fullness: 75,               // 飽食度 (0~100)，每小時自然 -2
    happiness: 60,              // 心情 (0~100)，每小時自然 -1
    evolution_stage: 2,         // 進化階段 (1=幼年, 2=成年, 3=最終)
    equipped_items: [3, 7],     // 裝備中的裝飾品 ID
    created_at: "2026-05-29"
}
```

### 4.3 互動行為與點數消耗

| 行為 | 點數消耗 | 效果 | 冷卻時間 |
|------|----------|------|----------|
| 餵食（普通食物） | 5 點 | 飽食度 +20, EXP +10 | 30 分鐘 |
| 餵食（高級食物） | 15 點 | 飽食度 +50, EXP +30 | 30 分鐘 |
| 玩耍 | 3 點 | 心情 +15, EXP +5 | 15 分鐘 |
| 洗澡 | 5 點 | 心情 +30, EXP +10 | 2 小時 |
| 摸頭（免費） | 0 點 | 心情 +3 | 5 分鐘 |

### 4.4 等級與進化系統

**經驗值曲線（指數成長）：**

```
升級所需 EXP = 基礎值 × 等級^1.5

Level  1 → 2:   50 EXP
Level  5 → 6:  168 EXP
Level 10 → 11: 474 EXP
Level 20 → 21: 1342 EXP
Level 29 → 30: 2342 EXP
```

```javascript
function expToNextLevel(level) {
    return Math.floor(50 * Math.pow(level, 1.5));
}
```

**進化階段：**

| 階段 | 等級區間 | 外觀變化 | 解鎖功能 |
|------|----------|----------|----------|
| 🥚 幼年期 | Lv.1~9 | 小型、簡單 | 基本餵食、摸頭 |
| 🐣 成年期 | Lv.10~19 | 中型、細節增加 | 解鎖玩耍、洗澡 |
| 🐲 最終型態 | Lv.20~30 | 大型、華麗 | 解鎖特殊動作、稀有裝飾 |

進化時播放 **特殊進化動畫**（3~5 秒），類似寶可夢進化效果。

### 4.5 裝飾商店系統

| 裝飾類型 | 範例 | 價格範圍 |
|----------|------|----------|
| 帽子 | 廚師帽、貝雷帽、皇冠 | 20~100 點 |
| 背景 | 廚房、公園、星空 | 30~150 點 |
| 配件 | 圍裙、蝴蝶結、墨鏡 | 10~50 點 |
| 特效 | 愛心泡泡、星星閃爍 | 50~200 點 |

### 4.6 自然衰減機制

寵物的屬性會隨時間自然下降，鼓勵玩家定期回來互動：

```javascript
// 每小時衰減（後端計算，前端每次開啟頁面時同步）
function applyDecay(pet, hoursElapsed) {
    pet.fullness = Math.max(0, pet.fullness - hoursElapsed * 2);
    pet.happiness = Math.max(0, pet.happiness - hoursElapsed * 1);

    // 飽食度和心情影響外觀
    if (pet.fullness < 20) → 顯示飢餓表情
    if (pet.happiness < 20) → 顯示難過表情
    // 但不會死亡！只是停止獲得經驗值
}
```

> 📌 **設計重點：寵物不會死亡或消失。** 長時間不玩只會讓寵物看起來餓/難過，回來餵食後立刻恢復。避免玩家因負面體驗而流失。

## 5. 資料庫擴充 Schema

在現有資料庫基礎上新增以下表：

```sql
-- ============================================
-- 寵物系統擴充表
-- ============================================

-- 寵物
CREATE TABLE IF NOT EXISTS pets (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id         INTEGER NOT NULL UNIQUE REFERENCES users(id),  -- 一人一寵物
    species         TEXT NOT NULL DEFAULT 'rice_bunny'
                    CHECK(species IN ('rice_bunny', 'bread_bear', 'veggie_dragon')),
    name            TEXT NOT NULL DEFAULT '小糰子',
    level           INTEGER NOT NULL DEFAULT 1,
    exp             INTEGER NOT NULL DEFAULT 0,
    fullness        INTEGER NOT NULL DEFAULT 100,     -- 0~100
    happiness       INTEGER NOT NULL DEFAULT 100,     -- 0~100
    evolution_stage INTEGER NOT NULL DEFAULT 1,       -- 1=幼年, 2=成年, 3=最終
    last_decay_at   TEXT NOT NULL DEFAULT (datetime('now')),  -- 上次衰減計算時間
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 裝飾品定義（靜態表，由管理員/種子資料填入）
CREATE TABLE IF NOT EXISTS pet_shop_items (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,
    category    TEXT NOT NULL CHECK(category IN ('hat', 'background', 'accessory', 'effect')),
    cost        INTEGER NOT NULL,            -- 點數價格
    sprite_key  TEXT NOT NULL,               -- 精靈圖 key（前端用）
    min_level   INTEGER NOT NULL DEFAULT 1,  -- 最低等級需求
    description TEXT
);

-- 玩家已擁有的裝飾品
CREATE TABLE IF NOT EXISTS pet_owned_items (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL REFERENCES users(id),
    item_id     INTEGER NOT NULL REFERENCES pet_shop_items(id),
    is_equipped INTEGER NOT NULL DEFAULT 0,  -- 是否裝備中
    purchased_at TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(user_id, item_id)                 -- 同一件不重複購買
);

-- 互動日誌（用於冷卻時間檢查 + 數據分析）
CREATE TABLE IF NOT EXISTS pet_action_logs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL REFERENCES users(id),
    action      TEXT NOT NULL CHECK(action IN ('feed', 'feed_premium', 'play', 'bath', 'pet')),
    points_spent INTEGER NOT NULL DEFAULT 0,
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_pets_user ON pets(user_id);
CREATE INDEX IF NOT EXISTS idx_pet_items_user ON pet_owned_items(user_id);
CREATE INDEX IF NOT EXISTS idx_pet_logs_user ON pet_action_logs(user_id, action);
```

## 6. API 擴充規格

所有 API 都需要 JWT 認證（`Authorization: Bearer <token>`）。

### 6.1 `POST /api/v1/pet/create` — 建立寵物

首次進入寵物頁面時呼叫。

```
Request Body:
{
    "name": "小糰子",
    "species": "rice_bunny"    // 初始只能選 rice_bunny
}

Response 201:
{
    "success": true,
    "data": {
        "pet": {
            "id": 1,
            "species": "rice_bunny",
            "name": "小糰子",
            "level": 1,
            "exp": 0,
            "fullness": 100,
            "happiness": 100,
            "evolution_stage": 1,
            "equipped_items": []
        }
    }
}

Response 409 (已有寵物):
{
    "success": false,
    "error": { "code": "PET_EXISTS", "message": "你已經有寵物了" }
}
```

### 6.2 `GET /api/v1/pet/status` — 取得寵物狀態

每次開啟頁面時呼叫。後端會先計算時間衰減後再回傳。

```
Response 200:

        "pet": {
            "id": 1,
```

### 8.1 精靈圖規格

| 資源 | 格式 | 單幀尺寸 | 說明 |

### 8.2 美術風格建議

- **風格**：像素風 (Pixel Art) 或 Q 版插畫
- **像素風優勢**：製作速度快、檔案小、適合獨立開發
- **色調**：明亮溫暖，與惜食系統的綠色環保主題搭配
- **參考**：類似「旅行青蛙」的簡約可愛風格

```javascript
// PetGame.js — 最簡可運行範例

import * as PIXI from 'pixi.js';

export class PetGame {
    constructor(canvasId) {
        this.app = new PIXI.Application();
    }

    async init() {
        await this.app.init({
            canvas: document.getElementById('pet-canvas'),
            width: 375,
            height: 400,
            backgroundAlpha: 0,   // 透明背景，用 CSS 控制底色
        });

        // 載入素材
        await PIXI.Assets.load([
            { alias: 'bunny_idle', src: '/mobile/js/game/assets/pets/stage1_idle.png' },
            { alias: 'bg_kitchen', src: '/mobile/js/game/assets/bg_kitchen.png' },
        ]);

        // 背景
        const bg = PIXI.Sprite.from('bg_kitchen');
        bg.width = 375;
        bg.height = 400;
        this.app.stage.addChild(bg);

        // 寵物精靈（靜態圖，後續替換為 SpriteSheet 動畫）
        this.pet = PIXI.Sprite.from('bunny_idle');
        this.pet.anchor.set(0.5);
        this.pet.x = 375 / 2;
        this.pet.y = 280;
        this.app.stage.addChild(this.pet);

        // 呼吸動畫（簡單 idle 效果）
        this.app.ticker.add(() => {
            this.pet.y = 280 + Math.sin(Date.now() / 500) * 3;
        });
    }

    // 餵食動畫
    async playFeedAnimation() {
        // 用 GSAP 做食物飛入效果
        const food = PIXI.Sprite.from('food_normal');
        food.anchor.set(0.5);
        food.x = 375 / 2;
        food.y = 0;
        this.app.stage.addChild(food);

        await gsap.to(food, {
            pixi: { y: 260, scale: 0.5 },
            duration: 0.5,
            ease: 'bounce.out'
        });

        this.app.stage.removeChild(food);
        // 播放寵物吃東西動畫...
    }
}
```

## 附錄 B：常見問題

**Q: 我需要自己建整個前端框架嗎？**  
A: 不需要。主系統已有 Hash Router 和 API 模組，你只需要在 `consumer-pet.js` 這個 view 裡面初始化 PixiJS canvas 和遊戲邏輯。

**Q: 點數系統的欄位在哪？**  
A: `users` 表的 `points` 欄位，已存在。每次惜食消費都會自動累計。你的 API 只需要扣除。

**Q: 可以用 TypeScript 嗎？**  
A: 主系統用 vanilla JS，如果你想用 TS 可以自己編譯，但最終產出必須是能被 `<script>` 直接載入的 JS 檔案。

**Q: 手機效能夠跑 PixiJS 嗎？**  
A: 夠。PixiJS 用 WebGL 渲染，一個 128×128 的精靈 + 幾個粒子效果，即使是低階手機也能 60fps。保持精靈圖總量在 2MB 以下即可。

**Q: 要支援離線遊玩嗎？**  
A: MVP 不需要。所有操作都需要連線驗證點數。未來可考慮用 Service Worker 快取遊戲素材加速載入。
